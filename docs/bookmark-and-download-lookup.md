# 收藏状态与下载查重修复

## 收藏状态

首页/搜索卡片持有 immutable 内容快照，详情页读取 ObjectPool。此前详情回源或镜像补齐只更新详情，没有把确认结果回放给已经存在的卡片；重建 View 也可能错过一次性收藏广播。

现在把当前账号的插画收藏状态单独记录，通过现有 payload/Diff 路径更新卡片：

- 详情确认、自己的官方列表响应、收藏/取消和失败回滚统一维护状态。
- 网络请求带账号和请求代次，早于新操作发出的响应不能把新操作覆盖回去；后续新请求仍可确认站外发生的取消。
- 旧磁盘状态不会因为加载得晚而变成“更新”的响应。
- Room 保存账号、插画 ID 和最后确认的布尔值；不依赖用户是否开启或完整注册收藏镜像。它不是待发送操作队列。
- 镜像只能提供正向证据。没有镜像记录仍是未知，不伪造“未收藏”；明确的取消/回滚不会被旧镜像改回红心。
- 页面重建会重放当前状态；滚动/布局及镜像变化只查询当前可见作品，避免深列表反复全量查库。
- 不更换推荐作品、顺序、隐藏标记或滚动位置，不重发收藏 API、自动下载、埋点或重新计算收藏数。仅有收藏状态变化时，不把旧列表元数据覆盖进较新的详情对象。
- 删除账号并清理本地数据时一并删除状态；异步写入须确认账号凭证仍存在，避免清理后被排队写入重建。

显示的是当前账号最近获得的可信信息。离线状态、镜像未覆盖且从未获得确认的作品不能凭空知道远端收藏状态；这类条目继续保留 unknown，不为每张缩略图自动调用 detail。

## 下载查重与查询成本

主业务库按 45→46 增量迁移，保留原下载行、文件名、路径、JSON、旧记录补回及完成页计数语义。新增状态表和两个非唯一索引，schema 由 Room 处理器生成。首次升级建立索引有一次性成本；不提供未经实机测量的耗时结论。

| 改动 | 行为与成本 |
| --- | --- |
| 存在性 COUNT 改 EXISTS | 首个符合条件的作品记录即停止，避免把同作品所有页数完；小说同号记录不当作插画已下载。 |
| 旧 JSON LIKE 改顶层 ID 解析 | 只分批读取尚未回填的记录，复用 DownloadIdExtractor，避免把嵌套作者 ID 或简介文字当作作品 ID；不重写旧记录。 |
| `(illustId,page,downloadTime DESC)` | 单页候选按新旧读取，整作品页查询按页码/时间排序，避免临时排序；较新的孤儿行仍可回退较旧可读文件。 |
| 文件名兜底轻量投影 | 只读文件名、路径和页码，不再为查找文件拖回整段作品 JSON。 |
| 时间＋文件名 keyset | 重命名扫描和画像下载采样使用两个索引范围，保留同毫秒记录，避免 OFFSET 随深度不断跳过历史行；兼容 API 24 SQLite。 |
| 遗留 DeduplicateArrayList | 单遍 HashSet 过滤保序，修复重复输入连首项一起删掉，以及详情 pager 追加页内重复的问题；维护修改后的成员索引。 |
| feeds 增量 identity 集合 | 追加时复用当前代集合；替换、删除或结构变化后重建。仅判重部分按新增批次处理，完整列表复制与 Diff 仍有随已有长度增长的成本。 |

继续保留真实 URI 可读性验证，记录存在不等于文件仍然存在；不使用 Bloom filter 的正命中来跳过用户下载，也没有引入全库图片相似度算法或更换数据库引擎。

## 验证范围

针对性回归覆盖：缓存灰心→详情确认红心、View 重建补回状态、镜像补齐与明确取消、只查询可见 ID、迟到网络响应、磁盘恢复顺序、账号隔离、遗留 JSON 误命中、小说 ID 碰撞、同时间分页与新表头插入、原 URI/旧记录、账号清理后的排队写入、详情追加去重和集合修改一致性。

设备迁移检查保留最早已提交的 v25→最新版本，并增加 Beta15 的 v45→v46：校验原下载路径/页码保留、新索引和状态表可用。最终发布报告从同一提交的 CI XML 汇总实际通过数，不把本地环境失败或模拟查询计划当作实机性能结论。

K80 Ultra 实机、长时间后台、极慢网络、满盘和第三方 SAF 故障场景未执行，需实际安装包验证。
