# 本地统计、用户画像与可选离线打标

入口：主页侧菜单 →「统计 / 用户画像」。首次进入分析本机记录，之后优先显示持久化快照，点击「更新统计」才重新扫描。页面复用 V3Palette、现有工具栏和日夜资源；平板内容最大宽度 720dp，按钮至少 48dp，支持字体放大。

## 数据口径与兼容

- 下载：扫描全部历史下载记录，跨账号共享；文件记录数不代表文件仍存在。作品按 ID 去重，小说与插画 ID 使用独立空间，同一作品多页不会重复计分。
- 收藏：仅当前账号本地镜像中的公开/私密插画与小说，明确展示首次同步完成的书架比例。进入统计页不会请求全量远程收藏。
- 综合：下载与收藏的作品并集，展示交集数量。镜像的作品元数据优先；下载、收藏的标签/作者/类型分布分别统计。
- 趋势：本地时区最近 30 天的下载文件记录。收藏接口没有收藏时间，不用作品发布时间伪造收藏趋势。
- 用户画像表示内容偏好，只汇总作品标签与作者，不推断用户个人身份属性。预测标签独立展示，不覆盖作品原有标签。

Room 46→47 仅新增 local_image_tags 表和 (sha256, modelVersion) 索引；保留原下载记录、URI、分页信息、查重规则和收藏镜像。统计使用 rowid/targetId 游标分页，每批 100 条；不加载整库 Illust 对象，不使用 OFFSET。扫描 O(N + T)，排名另需 O(K log K)，其中 K 为不同标签或作者数；保留作品去重键、标签/作者计数，最终快照只存前 30 排名。快照按账号保存；清理账号本地数据会删除对应快照。本机图片标签缓存跨账号共享。

## 按需模型与队列

用户主动点击「下载模型」才下载，走现有 QueuedModels / 统一管理器。原 ZIP 模型安装路径保留；新增带 SHA-256 校验的单文件安装模式。

- 基础模型：[SmilingWolf/wd-convnext-tagger-v3](https://huggingface.co/SmilingWolf/wd-convnext-tagger-v3)。量化与词表：[Smashinfries/wd-convnext-tagger-v3-mobile](https://huggingface.co/Smashinfries/wd-convnext-tagger-v3-mobile/tree/f574b1b7c24a41b275fa0169f5a6905402f58870)。Apache-2.0，许可与来源随 APK 提供。
- 固定 revision：f574b1b7c24a41b275fa0169f5a6905402f58870。
- 下载文件：wd-convnext-tagger-v3-quint8.onnx，使用标准 ONNX 图，不使用需要自定义算子的 `-mobile` 图。
- 大小：111,103,266 bytes（约 106 MiB），SHA-256：1de64bf089c186a342a27c7a48c17390e5bed0bc4aed8ae0450f356c6af05bca。
- 输入：448×448，float32 NHWC、BGR、0..255，白底补方、EXIF 方向校正。归一化在图内。输出与内置 10,861 条词表严格对应。
- 通用标签阈值 .35，最多 24 条；角色标签 .85，最多 8 条；不输出评级和画师类别。模型主要面向插画，其预测不等同于人工确认。

点击「分析新图片」提交持久化后台计划，复用现有 ENCODE 池，逐张检查暂停/取消，逐张保存进度。重启后可继续，已完成标签不依赖 Fragment 存活。每次任务固定下载表起始上界，新增下载在下一次任务分析；不自动开启耗电扫描。

静态图片逐张读取，GIF/视频/小说跳过，动画 WebP 不参与推理。一个 CPU 会话、2 推理线程；解码按尺寸采样到约 896 边长，再缩放到 448。模型会话在批次结束/暂停时释放，不保留原尺寸位图。单张失败不拖垮批次，模型加载失败终止批次并显示错误。

URI 与文件状态戳用于快速缓存命中；内容 SHA-256 用于相同字节跨文件复用。分辨率变化、服饰/光影等差分不会因相似而合并，也不删除文件。推理结果按 URI + 模型版本独立保存，画像按内容 SHA 去重。该缓存不替换下载管理器原有的作品/页码查重数据库。

## 空间、性能与验收边界

模型常驻文件约 106 MiB；下载与原子安装期间临时空间会额外占用。词表约 214 KiB，打标缓存随文件数线性增长，实际占用取决于标签长度。运行内存还包括 ONNX 权重/中间张量，不能从量化文件大小直接推算峰值，8GB RAM 并不等于已验证的运行峰值。

界面速度 = 新推理张数 / 本次累计活动全流程时间，包含读取、哈希、解码、推理、排队和缓存检查；排除暂停时段。缓存命中不算新推理。开发机已验证真实 INT8 图加载、输入输出和一次 CPU 推理，不能据此宣称 K80 Ultra 每分钟超过 10 张。

K80 Ultra 实测建议：首次处理至少 100 张混合尺寸图片，记录总活动时间、新推理/复用/失败数、平均张/分钟、峰值内存和温度；分别测试前台/后台、暂停恢复、杀进程重开、缺失文件及新下载后增量分析。目标 >10 张/分钟需以这些实机结果验收。

自动化覆盖统计去重与元数据、Room DAO、队列冷恢复/暂停/固定边界/内容复用、预处理与阈值、原 ZIP 与新单文件模型安装、账号数据清理、窄屏浅色与宽屏深色大字体。API 35 仪器测试覆盖真实量化 ONNX 算子路径及迁移，Release/R8 覆盖队列和快照 JSON 契约。小型量化测试图验证运行时接线，不替代完整模型的设备性能/准确度测试。完整 JUnit、lint、界面截图随 CI 工件/发布报告提供。

## 增量、断点与资源调度的准确边界

「分析新图片」仍会扫描历史记录并检查文件状态，只对没有可复用结果的内容推理；尚未实现仅按新增记录游标查询的增量索引。统计聚合会保留作品去重键和标签/作者计数，内存随不同作品数增长；统计页的扫描中断后重建快照，逐张断点属于图片打标任务。

队列重启恢复时，原 RUNNING 任务回到 QUEUED；用户主动暂停的任务保持 PAUSED，需要用户继续。结果写入与父任务检查点分开提交；进程恰好中断在两者之间时，下一次重看该文件，通过已保存的标签复用结果。原生推理不能在任意指令处立即中断，在返回后检查暂停。

当前实现共用统一管理器默认两个非组计划槽，打标占一个；本地分析使用后台优先级的 ENCODE 单槽，图片导出/动图转换共享此物理槽。普通 NETWORK/COPY 下载可并行，但仍有内存、CPU、磁盘带宽竞争，不能称为调度完全独立。后续可增加 ANALYSIS 单槽池，并让分析和编码共同遵守高内存任务预算；该独立资源池不在本次实现内。

## 缩放与模型能力

预处理保留宽高比、缩放后补白，不做中心裁切或强制拉伸。例如 2000×1000 → 448×224，上下各补 112 像素。长图的主要问题是缩小造成细节丢失。当前模型固定输入 448×448；保持总像素量而改变输入宽高，需要重新导出/适配并验证效果。长图分块可保留细节，但增加推理次数与能耗，本次未开启。

模型面向 Danbooru 风格二次元插画，使用固定词表预测人物/角色、服饰、动作、构图及背景等内容。它不是 OCR、自由描述模型或重复图片判定器，不能保证区分微小光影/液体效果等差分。原始分数不是校准后的正确率。本次不覆盖完整量化模型在手机上的准确度验证。

基础模型卡公布宏平均 F1 0.4419，不能解释为「准确率 44.19%」，也不能直接视为本次量化文件或用户图库的指标。量化发布者提供单张样图的分数对比，不能据此得出全数据集的量化损失。开发机 CPU 两线程单次纯推理约 0.429 秒，仅为运行格式验证，不包含文件读取、哈希、解码或排队，不能换算为 K80 Ultra 的吞吐量。模型卡未提供可引用的该手机测速。

开发机完整 INT8 模型的公开样图检查：使用上游 [power.jpg](https://huggingface.co/spaces/SmilingWolf/wd-tagger/resolve/main/power.jpg)，样图 SHA-256 `6fbc5cdb614aaa882067e80abbcc2773c284fdeabccd0ee269364504e9fc0995`，ONNX Runtime 1.24.3，等比缩放补白与 BGR 输入。输出 `power_(chainsaw_man)` 0.9951、`red_horns` 0.9588、`white_shirt` 0.9224、`black_necktie` 0.8630、`long_hair` 0.9222，与上游示例大体一致。此检查用于确认真实语义输出和标签映射，不是整库准确度评估，也不是手机速度测试；样图未随 APK 分发。
