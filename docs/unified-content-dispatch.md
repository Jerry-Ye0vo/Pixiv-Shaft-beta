# 统一物理调度

页面保存、缓存原图源、持久化复制和各类处理阶段统一向进程调度器登记“已准备好”的物理任务，再由数据库原子授权 NETWORK/COPY/ENCODE 名额。依赖文件、用户选择、目录锁和限流等待不登记为可运行阶段，避免队首任务占名额等待另一个任务。

当前查看的原图优先于新保存，自动离线快照为后台优先级。每等待 2 秒提升一级，最高与当前查看任务相同；同级按持久化入队顺序选择。当前查看持续到来时，旧后台任务仍可获得名额。被同一源/输出的活跃任务阻挡时，独立资源可以继续，避免阻塞整个池。优先级不抢占已经运行的流，取消请求直到流实际关闭才释放名额。

原图源不再每 250ms 轮询；入队、资源释放、用户操作和并发设置变化显式唤醒，另有单个进程定时器只负责等待任务的优先级提升。原图显示与保存复用同一源：显示消费者加入会提升源优先级，某一个消费者取消不会撤销另一个消费者仍需要的源。注册表淘汰时只取消没有观察者或文件等待者的预览。

内存任务票据只保留入队标志，不重复驻留整部小说正文或备份请求。内部处理阶段保留最近 1024 条诊断记录及所有活跃阶段，定期裁剪；旧下载记录、查重、页面迁移墓碑和已完成子任务复用凭据不在裁剪范围。

专项覆盖跨入口优先级、等待提升、同级顺序、资源阻塞让行、独立资源池、撤销/暂停、共享源提升、停止清理后释放、内部阶段裁剪及预览淘汰与保存并存。实际性能、低内存与处理器温控仍需真机测量。
