# Application update download handoff

ApkDownloadManager retains its existing process-owned parent and `update_apk_download_v2` MMKV JSON. Startup restores an incomplete download as paused; the user still explicitly resumes it. A fully downloaded set of parts may complete its final merge without re-downloading. Package identity, app signing and version configuration are unrelated to this functional change and remain unchanged.

An IO command actor serializes restore/start/restart and banner receipt updates. New work requires successful parent persistence. A restart cancels and joins the previous physical job, including body close and queue acknowledgement, before deleting/reusing part paths. UI entry calls only enqueue commands. Existing parent JSON fields, release selection, proxy policy and part filenames remain compatible.

Every probe request and every segment attempt enters ContentPhaseRunner and claims shared NETWORK capacity before client creation, partial truncation or a request. The eight planned workers are only planning width: actual connection counts are limited by the same capacity as original images and ZIP transfers. Active thread progress is incremented after claim, and retry delays hold no NETWORK permit. Cancellation closes probes and shard calls, including stalled sockets. Existing progress/stealing/stall monitoring remains; the cancellation acknowledgement occurs after actual cleanup.

Range responses are checked before append: status, exact requested start/end, total, body length when known, identity encoding and conflicting ETag. Requests include If-Range when a strong ETag or stored Last-Modified is available. Date fallback requires no ETag and at least 60 seconds between Date and Last-Modified. Old partials with no usable validation proof are rejected visibly rather than appended to an unrelated representation. Restored transient read timeouts are explicitly reset to the existing 20-second default; Gson's allocation otherwise bypasses that field initializer and can produce an unintended infinite timeout.

Final assembly requires COPY. Parts are copied in offset order into a sibling `.merging` file, closed/fsynced, length-checked and renamed. Existing final output is kept until the replacement is complete. The parent COMPLETED receipt persists before recoverable parts are deleted. A failed receipt or failed final commit retains parts so the final merge can be retried, including after process restart. The downloader still does not provide a new independent APK signature/hash policy; installation validation and existing release semantics remain.

Integration tests exercise the real manager with SQLite and MockWebServer: saturated shared NETWORK/COPY pools, rejected parent persistence with no HTTP fallback, all shard and merge claims, invalid ranges, restarting stalled probes and shard writers, existing-v2 paused restore/resume, validator changes, failed completion receipts with offline final-merge recovery, and atomic merge failure retaining existing output/parts. Existing update checker tests run on API28 and API35. Task-center projection and additional pause/cancel UI commands remain a later cross-type manager step.
