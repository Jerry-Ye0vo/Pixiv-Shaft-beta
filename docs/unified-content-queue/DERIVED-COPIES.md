# Durable local copies: translated images

ImagePageSaver remains a UI facade. Original-page saves still enter Manager; translated-image saves now reserve a ticket and submit a versioned `copy:` intent to the same content_queue.db. The admission actor captures the destination's storage choice, sanitized template path, MIME and overwrite policy. Changing global storage settings later cannot silently redirect an already accepted copy.

Every physical copy, including preservation of its temporary input, requires a shared COPY claim. Queued cancellation opens no output; cancellation remains available until the output transaction begins. Once output opening/finalization begins, cancellation returns false and the writer completes without interruption, matching the old page-save contract. A slot is returned only after streams, abort/finish handling and persistence have finished.

Translation cache eviction/replacement uses CopyInputReferences. Reservations and reference release perform no filesystem work on Main and never wait on an IO-held deletion monitor. The last deferred deletion runs on IO. The queue preserves input bytes with a private filesDir snapshot (temporary file, close/fsync, atomic rename) and checkpoints its hash/size under the current attempt before releasing the temporary-cache reference. A failure retains its owned input for retry; successful/cancelled copies remove their own snapshot. Input mutation/empty files are rejected. A process death before input preservation has completed can only replay the original input if it still exists; missing input is a visible failure, never a successful empty image.

An output URI is checkpointed before writing. After restart, a full hash/size match finalizes that same output instead of opening a renamed duplicate. An incomplete existing receipt is rewritten through the same URI; a missing receipt is opened again through the frozen policy. MediaStore pending visibility is finalized on recovery. Stale attempts cannot replace a newer checkpoint. This improves recovery for this adapter; it does not retroactively provide receipts for the old page/ugoira/export paths or claim atomicity across a provider and SQLite under power loss.

The existing `_translated` suffix, PNG content, success notification and optional bookmark action remain. Derived outputs never write the original downloaded-page table or original duplicate index. Saved-state notification precedes the successful UI transition, preserving the green-check ordering. Startup restores all unfinished copies and a bounded recent receipt projection; full history remains in the queue database for paged reads. The old download-manager screen/control projection for additional task types is a later migration step; this adapter exposes persisted state through the existing translated-image button UI and the shared core.

Tests cover admission/claim gating, cancelled waiting work, cache deletion references, noninterruptible output/capacity, failed finalization and retry from an owned input, restart receipt reuse, stale checkpoints, green-check ordering and original-library isolation, plus frozen destination behavior. The exact CI result belongs to the submitted SHA and is recorded in the PR. This stage does not change application ID, signing or version settings.
