# 小说导出接管

小说阅读、预读仍走原阅读链路。用户导出、旧 TXT 下载以及合并文件写入改为持久化 novel-export 父任务；最终写入共享 ArtifactPublisher。系列枚举和章节抓取的每次 API 调用分别领取 NETWORK，限流延迟和格式确认不占物理池。

冻结请求包含格式、路径、存储/覆盖策略、小说与 WebNovel 快照、明确类型的导出 token、已渲染 TXT 信息头；合集保存章节顺序、完整标题与 TXT 识别短标题/副标题。没有反射反序列化 sealed token，也不会在重放时根据新下载设置改名。

TXT/MD 内容生成、PDF 排版/生成、EPUB 压缩与图片编解码使用 COPY/ENCODE；EPUB 图片通过共享 URL 来源队列获取，持有文件引用到解码结束。失败重试与对话框位于这些物理阶段之外。关闭原页面只断开观察，进程重启可从冻结内容和完整私有产物继续。PDF 原生文档在异常路径也关闭。

最终 provider URI 在第一字节前写入检查点，保留字节数和 SHA-256。写入后记账失败可核对同一输出并补记，避免 Rename 再产生一份文件。用户取消在输出提交开始前生效；已经开始提交时不能把物理输出取消成未记账状态。文件系统/provider 与 SQLite 仍非同一事务，不宣称严格一次执行。

原下载历史以 NOVEL_KEY+小说ID 为主键，不增加新的库类型；不同格式仍 REPLACE 同一小说行。合集保持原先无单篇小说历史的约定。旧 TXT 的 Shaft Start/End 标记保持。

本阶段尚未将系列列表/章节获取整个过程变成可冷恢复的组父任务：已排队的最终文件可以恢复，尚未组装好的系列仍由原 UI 流负责。用户的中途停止保存截短合集、默认 TXT 检测插图后询问格式等语义保留，后续组计划迁移需保持这些行为。离线快照/动图父任务、全局优先级和统一列表仍继续实施；这不是全量完成报告。
