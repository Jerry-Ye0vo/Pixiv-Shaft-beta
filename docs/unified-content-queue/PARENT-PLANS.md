# Durable parent plans for the remaining entry adapters

A pipeline parent is an intention and a recovery coordinator. It must not occupy NETWORK or COPY while waiting for its own child stages; doing so deadlocks a capacity-one pipeline. ContentPlanQueue therefore stores parent records separately from physical `tasks`, applies a small planning width, and requires actual byte workers to obtain existing ContentPhaseRunner/other shared physical claims.

Private content_queue.db schema2 adds only `plans` and its indexes. A schema1 upgrade does not rewrite/drop any old task identity, state, payload, error, sequence or index. Room45 is unchanged. A plan stores immutable kind/family/request separately from mutable input/output checkpoint, state, error and attempt nonce. Claim and planning-width reservation are atomic; opening another helper does not recover live work. The single runtime recovers parent stop/commit intentions once at process startup and retires obsolete physical phase children before parents re-plan.

Admission, restore, command persistence and dispatch run on IO. The UI receives a memory-only ticket and observes a process-owned worker. Factories, workers and cleanup cannot submit another parent: dependencies must be physical child stages, while batch/series grouping must not retain a planning slot awaiting child parents. Duplicate unfinished families bind to a canonical identity. An explicit retry of the same stopped request preserves its checkpoint; a changed stopped request first retires its owned inputs. Failed admission never invokes a direct worker fallback.

Pause/cancel first records the request and cancels the worker. Planning width and physical permits remain occupied until the body and cleanup exit. Memory command gates and CAS-based acknowledgement prevent a concurrently accepted stop being overwritten by final-state publication. Final output commit rejects late pause/cancel; the smallest output transaction is non-interruptible, rather than the entire pipeline. A receipt/checkpoint must precede provider writes. Worker success requires an explicit committed output; metadata acknowledgement failure retains the reservation for recovery.

Policy yield is separate from explicit pause. Losing eligibility stops a running attempt and returns it to QUEUED after cleanup, retaining input checkpoints. A network/settings notification calls refreshEligibility; there is no per-plan policy polling. Becoming eligible cannot resume an explicitly PAUSED plan. Modules must supply a cheap predicate and preserve the existing scope of explicit user actions instead of opening every queued item.

Startup restores active plans and a bounded recent terminal projection per registered kind; complete history stays in SQLite. Cleanup removes only plan-owned inputs and runs before cancellation is published. Progress updates are coalesced and the command lock never spans filesystem work. Acknowledgement is still not an atomic transaction across SQLite and an external provider: typed handlers must validate immutable inputs, recover their output receipts and distinguish already committed output from missing/corrupt files.

Persisted copy DTOs and phase-intent JSON now have narrow R8 identity/field keep rules. An added release instrumentation method parses and re-encodes a fixed v1 payload including frozen destination, preserved-source hash/length and provider URI. Worker/coordinator implementations remain optimizable.

Tests cover actual v1->v2 file upgrade preserving old records, parent/physical capacity separation, family admission, stale attempts, stop/commit recovery, cancelled admission, delayed physical cleanup, capacity-one pipelines, commit cancellation boundaries, checkpoint retry and canonical aliases, database rejection without fallback, policy yield versus explicit pause, nested-parent rejection and the accepted-cancel/final-ack race. Existing page/source/copy/ugoira/snapshot/APK suites stay selected.

This commit is the parent foundation. Model, direct-ugoira, manual-snapshot and novel-export entry points still require concrete typed handlers and UI command wiring; it does not claim those paths have all migrated. Existing page/bulk/MMKV parents remain compatible rather than being forcibly converted before their adapters are ready.
