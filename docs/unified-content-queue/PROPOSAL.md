# 大图与内容离线化统一入队：方案分析

日期：2026-11-05。源码快照：`Jerry-Ye0vo/Pixiv-Shaft-beta/classic@79eea653e7f2e4d7723dcd1847676fd74f90e0e6`。

这是设计方案，不是已实现功能；未修改运行代码或发布 APK。

## 目标与范围

根据用户补充，统一范围确定为大图/完整动图获取，以及需要保留的内容离线化：用户主动保存、下载、导出，或用户启用策略产生的自动快照。范围内请求先向统一服务登记、入队，再由唯一调度器决定执行。空闲时入队后马上获得名额符合这个目标；业务入口不得绕过队列直接启动范围内的传输。

| 请求用途 | 是否纳入统一任务队列 |
| --- | --- |
| 首页、搜索、作者页的缩略图，头像和普通浏览预览 | 否，沿用即时加载、缓存及自身并发限制 |
| 小说日常阅读、翻章、正文预读 | 否，沿用阅读加载 |
| 大图原图获取，包含由浏览设置触发的原图及相邻原图预取 | 是；当前可见原图优先，预取低优先级 |
| 动图静态封面与预览 | 否，按缩略图/普通预览处理 |
| 动图播放所需 ZIP、帧及补齐资源 | 是；受自动播放/点击播放策略控制 |
| 单页保存、快捷多页、整部、多作品批量、保存译图、动图导出 | 是 |
| 手动离线快照、已启用策略触发的自动快照及补齐 | 是；快照作为父作业，素材作为其资源依赖 |
| 主动下载/导出小说 TXT、章节或整部系列 | 是；与小说阅读加载区别处理 |
| 主动下载模型、APK 等文件 | 是，保留各自校验与业务行为 |
| 打开已存在的离线快照、读取已有本地图片 | 否，直接读本地；损坏修复或补齐另行入队 |

大图按请求用途和资源质量识别，不能按控件尺寸或代码中 `large` 一词判断：`FragmentImageDetail.showLargePlaceholder()` 的 large 预览用于即时占位，属于浏览预览；真正原图获取进入统一队列。普通业务 API 请求不是用户下载任务，但下载作业依赖的元数据请求仍须在作业生命周期内处理，并保留 API 限流。

原图浏览缓存任务经过统一调度，但生命周期与主动保存不同：保存持久化，原图浏览任务通常短期保留；是否永久落库不影响“先入队才执行”的规则。仅查看原图不自动写入相册，也不形成原图已保存记录。点击保存时登记持久化的保存意图，复用同一资源传输和文件；离开查看器不能取消仍有保存意图的下载。

队列的网络上限只约束纳入的任务；缩略图和小说阅读有各自轻量并发与缓存约束，不宣称该数值是全应用所有网络请求之和。

“本地化落盘”在此指可保留的内容产物，不把每一次临时磁盘缓存、数据库状态或日志写入当成独立下载任务。相同缩略图在浏览场景可即时缓存，在快照场景则作为快照资源被保留；已有缓存通过本地提交复用，缺失才占网络名额。

## 当前实现的实际边界

1. 静态原图的单页、快捷多页和整部已进入 `Manager`；多作品批量由 `QueueDownloadManager` 拆页后提交给 `Manager`。
2. `Manager.startOne()` 直接派发，允许手动任务超过自动上限；`pumpAvailableSlots()` 才检查页面活跃数。这是同一个类内部的调度规则不一致。
3. `QueueDownloadManager.fillSlots()` 已计算“静态页面占用 + 动图在飞数量”。但这是批量提交前的快照计数，不是全应用共享的原子许可；`Manager` 的其他入队入口和自动派发只看自己的页面数，不能共同维持全局上限。
4. `ImageLoaderV3` / `ImageTaskRegistry` 直接启动显示任务。`Manager` 可等待和复制已有显示文件，但两者并没有唯一的传输调度权；顺序不同仍可能分别发起传输。
5. `ImagePageSaver` 的译图复制、单独动图保存、批量动图及播放引擎各有执行路径。动图已有部分共享缓存与互斥，不应在迁移中丢失。
6. 全应用还有 `ApkDownloadManager`、`ModelDownloadManager`、小说任务等。APK 下载内部会产生多个分片请求，因此限制“作业数”本身不能保证限制实际网络请求数。
7. 当前恢复信息分属作品队列表与页面恢复表；页面恢复表以文件名为主键，并存完整 `DownloadItem` JSON。`safeAdd()` 先放入内存再异步持久化，有短暂的进程退出丢失窗口。迁移应使用稳定任务 ID、明确去重键、共享元数据，并明确入队成功的持久化含义。

当前有可复用的存储门面 `Downloads/DownloadsRegistry`、MediaStore/SAF 后端、模板规则、StageStore 断点校验和原图缓存。统一调度不要求重写这些成熟部分。

## 方案比较

| 方案 | 价值 | 局限 | 适用性 |
| --- | --- | --- | --- |
| 修补旧 Manager 的入口和共享许可 | 改动较小，能先消除已知超限 | 状态、恢复与特殊流程仍分散，容易再次出现旁路 | 可作迁移第一阶段 |
| 所有内容进入单个严格 FIFO，由一个大型 Manager 执行 | 顺序容易理解 | 当前看图可能排在大量批量任务后面；编码和网络任务互相占位；类型逻辑集中 | 不推荐作最终结构 |
| 统一任务模型、唯一调度器、内部按类型与优先级排队、专业执行器 | 满足全部先入队，可统一恢复与并发，同时保持看图响应 | 需要迁移状态模型和旧入口，初期工作量较大 | 推荐最终结构 |
| 全部交给 WorkManager 或系统 DownloadManager | 可复用系统调度/后台能力 | 不能直接覆盖共享图片缓存、译图复制、动图编码和现有交互；仍需应用内编排 | 作为后台恢复机制或特定执行后端 |

不建议增加一个只转发调用的外层类，同时保留旧组件各自启动和计数。这会增加层级，不能保证统一调度。

## 推荐结构

```text
单页/多页/批量/译图/动图/原图浏览/离线快照/主动更新与模型/小说导出
                         ↓ enqueue
               统一任务服务与任务记录
                         ↓
                唯一调度器与资源分配
                         ↓
     文件传输 / 本地复制 / 动图处理 / 小说导出 / 更新与模型校验
                         ↓
             现有缓存、StageStore 与存储后端
```

专业执行器只能在调度器授权后运行，不能自行决定启动下一条。旧 `Manager` 可暂时保留为兼容门面；`QueueDownloadManager` 最终只承担批量分组、任务展开和结果汇总，不再分配传输名额。

### 入队、恢复与状态

- 对主动保存先在后台事务中落库，再允许执行；入队接口在提交成功后才确认“已入队”。不在主线程做数据库操作，也不持全局内存锁等待 IO。
- 初始字段包括任务 ID、类型、来源、分组、资源引用、输出目标、状态、优先级、重试时间和错误；大型作品元数据按需读取，避免每一页重复存储整部作品。
- 使用排队、等待网络、运行、写入、暂停、成功、失败和取消等统一状态；下载、解压、编码等细节属于任务阶段，不再由 UI 推断。
- 作品与批量是分组，页面和动图等是可执行任务；同一个任务只计一次，不把父分组当成额外网络任务。
- 暂停、继续、重试、提高优先级都是队列命令。手动继续某项只能授权该项，不得改变整个队列的 Wi-Fi 策略，也不得绕过容量限制。
- 启动恢复时将上次未完成的运行尝试转成可恢复状态，保留手动暂停与待网络原因；不假定进程能永远存活。
- 作业执行采用可重试与幂等提交。需处理“文件已提交、成功状态尚未落库时进程退出”的窗口；不能仅依赖内存回调或声称跨文件系统和数据库严格只执行一次。
- 每次执行具有独立的尝试标识，过期回调不能覆盖已经取消或重新启动的任务。

### 同一资源的共享与取消

- 把“取回资源”和“保存到某处”区分为可关联的任务。看图和保存同一原图，依附一个资源传输；传输成功后分别显示或提交输出。
- 去重需包含来源上下文、作品/页码、质量或版本及必要内容身份；保存去重还需包含输出位置、原图/译图版本、格式和用户覆盖意图。不能只按作品 ID 去重，也不能粗暴剥掉带认证或版本语义的 URL 参数。
- 用户选择“重命名再存一份”应保留新输出意图，不能被资源去重吞掉。
- 取消一个消费者不会取消仍被另一消费者使用的传输；离开大图后，已有保存任务继续。只有无消费者且无持久化保存意图时才取消临时取图。
- 保存过程中依赖的译图或编码文件要有稳定持有方式，避免进程恢复前被临时缓存清理。
- 入队时做原子任务去重和缓存乐观探测；执行前再次检查在飞任务、本地文件、权限、完整性与实际画质。缓存命中改走本地提交作业，不直接绕过队列，也不占网络名额。
- 旧快照的 assets 映射会把多个画质 URL 指向一份文件，不能仅凭原图 URL 命中就将预览存档当作原图。引用快照资源需结合 manifest 和实际资源规格；生成新记录时保留实际质量与来源。

### 离线快照

- 保留当前 manifest、assets、作品/评论 JSON 以及动图帧等格式。快照父作业负责选择画质、资源依赖、复制和最终校验，调度器负责授权；不再保留独立网络名额分配权。
- 快照中的图片、头像和评论素材均属于该作业，即使它们在普通浏览场景属于即时加载例外。缓存可用则复制到快照目录，缺失则通过队列获取。
- 自动快照继续遵守用户开关、配额和淘汰策略，低优先级执行；不能因不属于主动点击而绕过统一管理。当前自动引擎跳过 ugoira，迁移不顺便改变该规则。
- 保留“预览画质/原图”和“是否含评论”等快照选项，不因为统一管理就自动升级所有快照为原图。
- 完整资源与清单校验通过后才发布快照完成状态；失败或退出保留可恢复任务，不把未完成目录标为完整快照。
- 已有快照直接本地读取，不要求联网或等队列，也不需要重新下载。正式与自动快照身份、转正、清理和用户图库的保存记录分别管理；同一资源被多个产物引用时，清理某一缓存不得破坏其余产物。

### 并发与优先级

统一管理不等于所有工作共用一种名额。调度器应同时管理：

- 作业并行数：用户同时处理多少个保存任务。
- 网络请求数：真正占用连接的传输和分片。共享同一传输的消费者不重复占名额。
- 编码资源：动图等内存和 CPU 开销大的阶段单独限额，初始保守串行，实测再调整。
- 本地写入：复制、存储提交等使用有界并发，不占网络名额。

这些限制由同一调度器授权，不能由多个管理器各自读快照再启动。动图编码时释放网络名额；等待共享任务时不重复占用该传输的网络名额。避免持有许可等待另一个也需要同类许可的任务。

内部可分当前可见原图、主动保存、批量任务和相邻原图预取等逻辑队列。当前可见原图通常优先，批量任务使用等待时间提升优先级或公平轮转，避免长期饿死。低优先级预取需要数量上限，并在不再需要且没有保存消费者时取消。API、主机及流量策略可另外约束。

优先级只影响下一次派发：全部名额已占满时不会凭空获得额外名额。若要求立即响应，需要设计交互预留预算，或让支持断点的后台传输安全暂停后让位；并发为 1 时尤其需要明确该取舍。

缓存命中可直接完成请求，不需要故意延迟。所有原图实际联网的入口必须接入统一传输调度，包括一级详情页的原图显示设置及查看器相邻原图预取，不能仅改保存按钮。缩略图/large 占位预览及小说阅读不入此队列，保留原有缓存和解码能力。

### UI 与 Android 后台

可以保留“批量—正在—已完成”，三个页面改为同一任务数据的不同视图。队列中明确显示等待、下载、写入、编码或失败；原图浏览和预取标明缓存用途，与主动保存区分。已完成的浏览缓存不计作用户已保存的文件。

统一服务需明确“全部暂停”是否包含原图浏览任务，并让按钮文案和状态一致。已暂停的范围内任务不能以浏览为由绕过调度。未纳入的缩略图与小说日常阅读继续沿用各自加载策略。

持续下载使用适合当前 Android 版本的前台执行机制；WorkManager 可协助可延迟的恢复与唤醒。统一队列保证记录与恢复能力，不保证应用被强行停止后仍能持续执行。

## 渐进迁移顺序

1. 定义上述调度契约、任务身份和状态；补齐日志、版本和系统退出记录，保留当前故障的诊断能力。
2. 用统一服务收口静态图片保存的所有入口；删除 `startOne()` 的直接派发语义，统一执行资格和许可。旧接口仅转成队列命令。
3. 迁移两套旧恢复数据；做幂等导入与迁移标记，按实际文件和任务身份核对重复，不清空用户未完成任务。新队列启用后，旧自动消费者不得继续抢跑同一批任务。
4. 让批量层仅产生/展开子任务并汇总，移除与页面管理器重复的容量分配。批量数据仍按分页或分批展开，不一次加载所有页到内存。
5. 接入译图、动图、原图浏览和快照作业；保留原图/译图语义、缓存共享、GIF/MP4、快照清单和命名覆盖策略；普通缩略图/占位预览和小说阅读保持即时加载。
6. 将主动 APK 下载分片、模型下载、小说导出等文件任务接入相同服务，保留各自校验与业务行为。按上述纳入/排除清单完成调用入口审计后，才称为目标范围全部统一。
7. 通过兼容门面逐步替换调用者，最终禁止业务层直接创建传输或启动 worker；同一批任务只允许新旧执行路径中的一个拥有执行权。

每阶段单独验收，不把迁移中间状态描述成已全部统一。签名和 `.beta` 应用标识沿用已有约定；本分析不产生新构建。

## 核心验收条件

- 每个纳入范围的传输都有入队记录和有效授权，没有入口能够绕过；忙时反复保存/继续不会增加上限。
- 静态图、动图、APK 分片和模型混跑时，仍遵守所定义的全局网络与作业预算。
- 大批量任务在运行时当前大图可按策略获得服务，批量任务也有进展；并发 1 和满额时的等待行为可解释。
- 批量任务排队或暂停时，首页/搜索缩略图和小说阅读仍可加载；主动小说导出按统一队列策略运行。
- 原图仅浏览不写相册、不误标已下载；浏览中点击保存复用已有传输，退出浏览后保存任务仍继续。
- 手动/自动快照按同一调度授权执行，缓存充足时零新增内容网络请求；无原图的预览快照不冒充原图来源，已有快照可离线打开。
- 同一资源看图和保存共享传输，取消其中一个不会破坏另一个。
- 任务确认入队后终止进程、完成复制前后终止进程、取消与重试交错时，记录可恢复且不过期覆盖，不误标译图为原图。
- 权限变化、SAF 失效、存储不足、HTTP 错误和断点校验失败均形成明确状态与异常记录，而不是无限转圈。
- 任务规模大时分页读写，界面不因序列化和数据库锁等待阻塞。

统一调度能够解决已确认的旁路和容量不一致；最近日志中的进程退出仍需系统退出记录或对应堆栈验证，不能因架构调整而宣称已定位或修复。
