# Shared original sources and static page output

`ContentQueueRuntime` owns process-death recovery for the independent queue. Both the page adapter and the original-image source adapter use that authority; opening either must not recover away the other's live attempts.

Static page saves now hold a COPY permit for preparation, source waiting and output commit. Their source is an independent durable NETWORK task shared by original-image browsing and saving, keyed by the exact URL including query/version semantics. The page copy resource key is separate from the source transfer key, so a page waiting for its source cannot reserve the NETWORK capacity/resource that its source needs. COPY capacity remains conservative and includes dependency waiting until a later phase splits the page orchestrator further. GIF page ZIPs retain the previous NETWORK path; static aria2 RPCs retain page authorization, while actual NAS transfers run remotely outside application resource accounting.

Shared network workers reuse the existing page client policy (HTTP/1.1 and no display-progress interceptor), retaining DNS, proxy, TLS and timeout settings. Cache trim requests are coalesced onto one IO scanner. Source acquisition checks the exact-URL original cache on IO before admission, commits a durable source intent before claiming NETWORK, and probes cache again before fetching. A cache hit returns a protected reference without a network claim. A single shared source runs for view-first and save-first ordering. Every consumer observes shared progress; cancelling one consumer leaves others running. The last cancellation requests shutdown; the worker retains its NETWORK permit and its own cache pin through socket/body exit and durable acknowledgement. A stopping source must retire before another attempt can start. One shared read-stall retry budget covers the existing image option and an attached save's lowered-timeout option; the registry disables its separate outer retry for original sources.

A save retains a cache reference through the entire local copy. LRU trimming, cache clear and orphan sweeping skip pinned cache/stage/metadata files. Releasing one consumer twice cannot release another's pin. Cache pins are process-local: after process death, durable page/source records and validated partials provide recovery. Temporary browse-only source tasks resume on demand; they are not all automatically fetched during startup. Successfully browsed sources are cache records only and never inserted into the user's completed-download library.

Old stopped static page records are rebound in place from NETWORK/source ownership to COPY/page ownership; task IDs, payloads and terminal tombstones remain. Live attempts cannot be rebound. Old network partials are copied to the source staging directory only with a matching full URL and plausible manifest length, retaining validators and the original journal. Full locally copied page stages now receive a complete-length manifest before output commit, so failed output commits remain recoverable. Direct-file output from a full source overwrites an old partial instead of appending the full image to it. No Room schema, done-table, history or downloaded-page probe change is included.

Explicit original and preview registry channels have distinct keys. An original request cannot inherit a Glide preview fetcher merely because a preview with the same literal URL was registered first. Thumbnail/large preview browsing and novel reading remain immediate exceptions. Other output types and fetch entrypoints remain on the migration list; the raw resumable fetcher instance remains the authorized source worker and a test seam, while its production companion routes through the source queue.

Remaining: priority/fairness and prefetch retirement, phase-level COPY release during dependency waiting, durable output receipt reconciliation, model/APK/novel exports, translated-image copies, full ugoira and snapshot pipelines, source tombstone garbage collection, and device reproduction of the unclassified process exit. The original-image file itself may still be evicted after its display fetch returns; only consumers retaining an explicit source loan are protected through use. This phase does not alter bitmap decoding or claim to have fixed the earlier image-page process termination.
