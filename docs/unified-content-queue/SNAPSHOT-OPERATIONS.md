# 快照导入、归档、转正与清理

管理操作提交持久 snapshot-operation 意图。导出 ZIP 在私有目录生成，再向用户选择的文档或目录发布；实际 URI 在第一字节前写入回执，写入失败保留归档重试，不重新压缩。恢复核对同一 URI 的字节摘要。文档 provider 与 SQLite 没有共同事务，创建文档与记录 URI 之间的极小窗口仍可能留下零字节文档，不能宣称严格一次执行。

导入保留流式解压，避免在完整解压目录之外再占一份大 ZIP。通过持久文档授权重开中断来源；完整暂存目录校验后保存逐文件摘要，之后可以离线安装。校验在移动旧快照之前完成，暂存和目的地都在应用 filesDir，最终采用同文件系统目录替换。进程中断的旧备份优先恢复，已完成目录按摘要复用；取消也不能遗失唯一旧备份。

转正先校验资源，用临时文件加 fsync/rename 提交正式 manifest，再移除自动标记。删除保留原 Boolean API 和“实际删除完成后返回”的约定；现有管理页已在 Dispatchers.IO 调用，自动配额循环因此不会因异步假成功而反复扫描。

生成/导入/转正/删除持有目录写许可，归档持有读许可；等待目录使用权期间不占 COPY/ENCODE。相同目录嵌套调用识别已有许可，禁止把正在持有的读许可升级为写许可而自锁。不同目录独立。动图缓存复用这套读写门，既有七项缓存并发回归继续覆盖。

旧 .backup_* 不再被无条件删除。可识别的备份在原目录缺失时通过持久恢复任务还原；原目录有效时保留旧备份，无法识别的内容保留。已下载表、查重表、小说历史和快照 v1 内容格式保留。

ZIP 的父目录路径与归一化重复条目改为明确拒绝，合法 .shaftsnap 不受影响；Windows 分隔符、正常归档往返继续兼容。流式解压/压缩有取消检查，解压文件数/展开大小限制为 10 万/128 GiB。

本轮新增21项专项（管理操作15、目录许可4、ZIP2），预计390项；实际结果以当前提交 Actions 为准。小说系列组、旧动图回放出口、全局优先调度、统一列表和最终完整验收仍在继续。
