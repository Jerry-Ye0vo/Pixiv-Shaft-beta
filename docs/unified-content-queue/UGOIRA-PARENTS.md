# 动图保存父任务

详情页直接保存、响应中带元数据的自动保存和批量保存现汇入 ugoira-save 父任务。请求冻结 GIF/MP4 两种目标、命名、存储和覆盖策略；实际编码降级 GIF 时选择冻结 GIF 目标，回执及旧已下载表按实际格式记账。

保留先利用播放缓存和 MP4/RIFE 准备的行为。网络元数据、ZIP、解压和编码仍使用共享物理许可。生成的成品先进入该父任务独立的私有目录，再通过 ArtifactPublisher 发布，固定 provider URI 和输入摘要。历史记账失败可以复用同一产物和输出补记，避免再编码与 Rename 副本。

批量 download_queue 行保留，由 row.id 对应稳定的 child family。该行重放允许复用成功父任务；文件已发布而批量行未来得及确认成功时，不会再次生成副本。用户再次主动保存仍是新意图。批量暂停/清空明确转发到自己的父任务，单纯观察协程关闭不影响其它直接保存。

清 GIF 缓存先等正在读取缓存的 pipeline/保存退出，等待期间不占 COPY。已有读者并行，新读者不会越过已等待的清理；取消要等 reader 的 finally 真正结束。清理、坏帧目录清除和残留清扫再领取 COPY。保存生成临时 GIF 使用父任务独立路径，并在最终复制期间持有每作品文件锁。

GIF 编码要求帧非空、各帧可解码、addFrame 和 finish 成功；遇到坏帧明确失败，不跳过坏帧后宣称成功。请求取消在逐帧边界检查，编码槽在实际退出后归还。

兼容旧的仅播放 ZIP 下载行，继续走原页面持久记录和共享物理许可；旧 OutPut/编码桥仍需在后续清单中确认所有历史回放的成品写入都转到持久回执。全量迁移、快照父任务、组恢复与最终统一列表尚未完成。
