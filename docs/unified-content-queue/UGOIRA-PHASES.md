# Ugoira physical-stage handoff

Playback and bulk-save ZIP transfers now enter ContentPhaseRunner before creating an HTTP client or touching the target. They atomically claim the same NETWORK capacity as original-image sources and legacy page transfers. Resource identity serializes writers to the same ZIP; a second caller checks for completed bytes again after obtaining its claim. The existing Range/If-Range, validator, 200/206/416, proxy, header and .part recovery behavior remains in the raw worker.

Cancellation closes the actual OkHttp call, including a request stuck before response headers. A requested stop never returns capacity while its body, output streams or finalizers are still running. The queue records terminal state only after physical cleanup. Failed acknowledgements retain the database reservation until process recovery.

Extraction uses COPY. JPEG frame copies use COPY; PNG-to-JPEG conversion, RIFE interpolation, video and GIF encoding use ENCODE. All adapters share one encoder slot. The claim is acquired before EGL initialization; the existing video body remains without suspension points while EGL is active. Local file locks and safety semaphores remain as resource guards rather than global authorization. No NETWORK claim spans extraction or encoding, so a capacity-one pipeline can advance stage by stage. Nested phase claims are rejected to prevent self-deadlock.

Bulk output and legacy OutPut ugoira output open their backend only inside an admitted stage. Existing-file copies use COPY. GIF encoding directly into a provider conservatively retains ENCODE through stream close and onFinish; no nested COPY claim is taken. Both output paths abort partial output on failure, and publish original completed-library records only after successful provider finalization. The legacy GIF executor delegates to the common queued encoder and preserves progress callbacks.

ContentPhaseRunner is a physical child-stage adapter. Its JSON contains version, owner, phase, resource, context and submission time; it does not pretend a coroutine closure is a replayable full job. On cold startup the single ContentQueueRuntime recovery owner retires abandoned phase children; existing persisted bulk/page parents replay and recheck artifacts before creating fresh children. A second adapter initialized in the live process cannot revoke another worker. Playback cache generation remains demand-driven.

Remaining ugoira work includes a typed persistent parent for every direct-save fast path, frozen output settings and URI receipts across the entire parent pipeline, saved-output/input leases across manual GIF cache clearing, and complete task-center control projection. These changes do not claim full ugoira or full-application migration. Snapshot/avatar copies, APK/model and novel exports still require their own adapters. Application ID, signing, version configuration, Room45 and existing original completed/duplicate queries are unchanged.

Regression covers shared network saturation, no request/client construction before admission, waiting cancellation, late cache reuse, overlapping playback/save target requests, stalled socket cancellation, delayed cleanup holding capacity, same-resource exclusivity across pools, capacity-one phase transitions, nested-claim rejection, single-owner recovery, plus the existing ZIP protocol/resume and GIF timing tests. Device slow-network/background/process-death verification remains outstanding.
