# Beta 统一下载管理

## 同步基线和行为

以官方 classic 的 `6f49fbe0b47c32e1ef6d7e994f551743f0f17f07` 为同步基线，包含最终合并的 #1317 原图续传、共享缓存及缓存配额设置。
大图页单页下载沿用 4.7.1 的方向，进入现有 `Manager`；没有回退整个应用或替换官方的新下载后端。

- 下载管理继续使用“批量 → 正在下载 → 已完成”三个左右滑动分区；移除“正在下载”内的单张保存子页。
- 原图单页保存、快捷选中多页及整部下载共用 Manager 的任务列表、下载限制、暂停、继续、失败重试和持久化。批量页仍负责整部作品的规划。
- 大图页按钮只控制当前作品的当前页：正在下载时暂停，暂停/失败/等待时继续，没有任务时按原图分辨率入列。不会调用整队或整部开始。
- 快捷“选择多页下载”菜单和长按入口保留，选择面板复用已有缩略图、全选、仅当前页、选未下载；只下载选中的页，按设置中的默认分辨率下载。
- 已完成记录仍按实际落盘的页数计算；下载 3 张不代表整部 20 P 已完成。清空实时队列也不能直接判定下载成功。
- 翻译结果是派生文件，继续用原有译图保存方式，与原图分开命名，不会污染原图的已下载记录。

旧 Beta 的 `image-page-saves.properties` 在 Manager 恢复前迁移到现有 Room 下载表。数据库事务成功后才清空旧日志；失败保留日志，且不阻塞其他已有队列恢复。稳定任务标识和文件名避免中断重试重复入列；已成功写入且仍能读取的文件不会再次下载。旧失败保存作为可继续的未完成任务导入，恢复状态及是否自动启动遵循 Manager 原有规则。

Beta 包名、固定签名和小版本自动递增属于独立构建配置，继续保留。此次不修改上游已关闭的 #1319。

## 与官方功能范围的关系

热度预览使用 Pixiv 接口，不需要借号热度排序；相同账号、设置和源码下，Pixiv 浏览及本地功能可保持一致。应用服务的鉴权、服务端授权、广场、聊天等能力不能仅靠同步源码保证与官方发行包一致。源码也仍有应用配置和统计请求，“使用热度预览”不代表完全不访问应用服务。

## 验证

开发分支的 `Unified download verification` 执行完整 app 单元测试、Room schema 检查及 app lint，并上传测试报告；正式合入后原有完整 CI 和固定签名 Quick test APK 工作流继续运行。

新增专项测试覆盖：只投影当前页进度；可变队列的不可变 UI 快照；暂停、失败和蜂窝等待状态；旧任务迁移、数据库失败事务回滚、日志保留、重复导入去重、已下载文件存在性和非法页码。

手机验收：

1. 设置为“不自动下载”，在多页作品下载单页和任选 3 页，确认统一出现在“正在下载”，且未选页面没有入列。
2. 从大图页恢复某一页，确认其他页和其他作品仍暂停；核对管理页与当前页的进度、暂停和重试状态。
3. 下载中退到后台、杀进程再打开，确认任务恢复；在 Wi-Fi 限制及蜂窝网络下核对等待与手动继续。
4. 使用旧 Beta 留下单张保存任务后覆盖升级，确认任务迁移；完成后“已完成”只统计实际落盘页数。
5. 查看译图时保存，确认原图文件和下载记录没有被译图替换。
6. 深浅主题、窄屏及放大字体下检查三个分区与多页选择面板。

自动化测试不能替代上述真实设备、网络和系统后台限制测试。
